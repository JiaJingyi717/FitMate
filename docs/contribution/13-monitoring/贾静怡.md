## 遇到的问题和解决

1. **问题**：仅有简单 `{"status":"up"}`，不满足作业对 `timestamp`、`version`、`checks` 的要求。  
   **解决**：抽取 `get_health_payload()`，增加数据库 `SELECT 1` 与 UTC 时间戳，对外仍用 `ok()` 统一格式。

2. **问题**：Docker 健康检查频繁访问 `/health`，导致 `/api/metrics` 中 `requests_total` 虚高。  
   **解决**：`metrics.py` 默认跳过 `/health`、`/api/health`、`/api/metrics` 路径。

3. **问题**：阿里云构建 backend 时 `pip install` 连接 `pypi.org` 超时。  
   **解决**：在 `backend/Dockerfile` 的 `pip install` 增加 `-i https://mirrors.aliyun.com/pypi/simple/` 与 `--default-timeout=120`（部署监控功能时需重新 `build` 后端镜像）。

4. **问题**：本地 `curl http://127.0.0.1/health` 无输出。  
   **解决**：开发 Compose 后端映射在 **5000** 端口；Windows 使用 `curl.exe` 而非 PowerShell 的 `Invoke-WebRequest` 别名。

## 心得体会

监控作业与云服务部署是连贯的：健康检查不仅要「能返回 200」，还要在 JSON 里说明**数据库是否可用**；日志用 JSON 行输出后，在服务器上 `docker compose logs` 即可截图交作业，无需额外装 ELK。部署到国内 VPS 时，构建镜像与监控能力要一并考虑网络（pip 镜像源），否则容易出现「代码已写好但镜像构建失败、线上仍是旧版本」的情况。`/api/metrics` 用进程内计数器即可满足课程要求，后续若上 Prometheus 只需改 exposition 格式，架构可平滑扩展。
