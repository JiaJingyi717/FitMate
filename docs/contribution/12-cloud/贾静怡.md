### 4. 问题解决

| 遇到的问题 | 解决方案 |
|------------|----------|
| Docker 构建 `pip install` 无法下载 `gunicorn`（PyPI 超时） | 在 `backend/Dockerfile` 的 `pip install` 增加 `-i https://mirrors.aliyun.com/pypi/simple/` |
| 后端 `Restarting` / 登录 500 / `Access denied for user 'root'` | 保证 `.env` 中 `MYSQL_ROOT_PASSWORD` 与创建数据卷时一致；勿随意 `down -v` |
| `Table 'fitmate.articles' doesn't exist` | 修复 `schema_mysql.sql` 后重建或依赖 `app.py` 迁移补表 |
| 线上视频仍为 `example.com` 假链接 | 部署含 `fix_demo_video_urls()` 的新后端并 `restart backend` |
| 更新代码时误删 `.env` | 更新前 `mkdir -p /tmp/fitmate-keep` 并 `cp -a .env secrets`，或从 `fitmate-backup` 恢复 |

## 心得体会

云服务部署不仅是「把代码放上网」，更要处理好**配置与数据持久化**：`.env` 与 MySQL 卷密码必须一致，更新代码时先备份密钥。国内 VPS 上构建镜像要优先考虑 PyPI/Docker Hub 镜像源，否则容易出现依赖装到一半失败的现象。用 Compose 把前端、后端、数据库固定在同一网络里，浏览器只访问 80 端口，既符合作业「生产环境」要求，也降低了 CORS 和暴露数据库的风险。后端在启动时执行 `seed_all()` 和 `fix_demo_video_urls()`，可以保证线上演示数据与本地开发一致，减少「库里有旧数据、页面却显示占位图」的问题。
